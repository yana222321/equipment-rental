# Ремонтная мастерская «Мастер+»

Полнофункциональное веб-приложение для сервисного центра: заявки на ремонт, каталог услуг,
личный кабинет клиента, рабочее место мастера, панель администратора и статистика с графиками.

**Стек:** Python 3.12+ / FastAPI, SQLAlchemy 2.x, SQLite (по умолчанию) или PostgreSQL,
JWT + bcrypt, ванильные HTML/CSS/JavaScript без внешних CDN.

---

## Быстрый старт

```powershell
# 1. Виртуальное окружение (Windows)
py -3.12 -m venv .venv
.\.venv\Scripts\activate

# 2. Зависимости
pip install -r requirements.txt

# 3. Запуск
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

При первом запуске база **создаётся и заполняется демо-данными автоматически**.

- Приложение: <http://127.0.0.1:8000/>
- Лендинг из макета: <http://127.0.0.1:8000/landing/>
- Swagger UI: <http://127.0.0.1:8000/docs>
- OpenAPI 3.0.3: <http://127.0.0.1:8000/openapi.json>
- Проверка доступности: <http://127.0.0.1:8000/api/health>

### Демо-аккаунты

| Роль | Email | Пароль |
| --- | --- | --- |
| Клиент | `client@workshop.ru` | `client123` |
| Клиент №2 | `client2@workshop.ru` | `client123` |
| Мастер | `master@workshop.ru` | `master123` |

На странице входа есть кнопки быстрой подстановки демо-данных.

## Возможности

### Публичная часть
- Лендинг с формой быстрой заявки, преимуществами и этапами ремонта.
- Каталог услуг с поиском, фильтрами по категориям, ценами и сроками.
- Форма заявки: валидация полей, загрузка фото устройства, черновик для гостя
  (после входа данные восстанавливаются).
- Регистрация и вход, восстановление сессии, защита маршрутов по ролям.

### Клиент
- Личный кабинет со списком заявок, KPI и фильтрами по статусам.
- Карточка заявки: смета, запчасти, история статусов, фото, документы.
- Отмена заявки на ранних этапах.
- Просмотр электронной квитанции и акта с QR-кодом (`/r/{token}`).

### Мастер
- Два списка: «Мои заявки» и «Свободные», поиск и фильтр по статусу.
- Взятие заявки в работу, смена статуса с комментарием и стоимостью работ.
- Списание запчастей со склада, возврат на склад, пересчёт итоговой суммы.
- Формирование квитанции и акта выполненных работ с QR-кодом.

### Администратор
- Все заявки: поиск, фильтр по статусу/мастеру, назначение мастера, просмотр карточки.
- CRUD услуг (категория, цена, срок, описание).
- Сотрудники: создание мастеров/администраторов, редактирование, удаление.
- Склад: CRUD запчастей, быстрое изменение остатка, контроль дефицита.
- Статистика: KPI, заявки и выручка по месяцам, статусы, топ услуг, загрузка мастеров,
  дефицитные позиции. Графики построены на CSS/SVG без сторонних библиотек.

### Статусы заявки

```
new → accepted → diagnostics → in_progress ⇄ waiting_parts → ready → completed
                                      ↘ canceled
```

Переходы валидируются на бэкенде и дублируются в интерфейсе мастера.

## Структура проекта

```
app/
  main.py          # FastAPI, lifespan, OpenAPI 3.0.3, SPA-раздача, публичный чек
  config.py        # настройки из переменных окружения
  database.py      # SQLAlchemy engine/session
  models.py        # 7 таблиц + статусы и переходы
  schemas.py       # Pydantic-схемы и валидация
  security.py      # bcrypt + JWT
  deps.py          # текущий пользователь, проверка ролей
  serializers.py   # сериализация заявок, услуг, запчастей
  queries.py       # выборки с eager-loading
  seed.py          # демо-данные
  receipts.py      # HTML-документ с QR (SVG)
  routers/         # auth, services, client, master, admin, stats, uploads
frontend/
  index.html       # SPA-оболочка
  static/css/      # тема и адаптивность
  static/js/       # api, роутер, графики, формы, экраны по ролям
  static/uploads/  # загруженные фото устройств
landing/
  index.html       # свёрстанный лендинг Rapier (из PDF-макета)
  css/style.css    # стили лендинга
  js/main.js       # мобильное меню, поиск, год
  assets/img/      # изображения, извлечённые из макета
tests/smoke_test.py
requirements.txt
workshop.db        # создаётся автоматически
```

### Таблицы БД

`users`, `services`, `spare_parts`, `repair_orders`, `status_history`, `order_parts`, `receipts`.

Связи: заявка → клиент/мастер/услуга, история и запчасти → заявка, квитанции → заявка.
Стоимость заявки = работы + запчасти; остатки списываются/возвращаются транзакционно.

## API

Все защищённые эндпоинты принимают `Authorization: Bearer <JWT>`.

| Метод | Путь | Роль | Назначение |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | — | Регистрация клиента |
| POST | `/api/auth/login` | — | Вход, выдача JWT |
| GET | `/api/auth/me` | любая | Текущий пользователь |
| GET | `/api/services` | — | Каталог услуг (`q`, `category`) |
| GET | `/api/services/categories` | — | Категории услуг |
| POST | `/api/client/requests` | client | Создать заявку |
| GET | `/api/client/requests` | client | Мои заявки |
| GET | `/api/client/requests/{id}` | client | Заявка с историей и документами |
| PATCH | `/api/client/requests/{id}/cancel` | client | Отменить заявку |
| GET | `/api/master/requests` | master | Заявки (`scope=mine\|available`, `status`) |
| POST | `/api/master/requests/{id}/take` | master | Взять заявку |
| PATCH | `/api/master/requests/{id}/status` | master | Сменить статус/стоимость |
| POST | `/api/master/requests/{id}/parts` | master | Списать запчасть |
| DELETE | `/api/master/requests/{id}/parts/{part}` | master | Вернуть запчасть |
| POST | `/api/master/requests/{id}/receipts` | master | Сформировать документ |
| GET | `/api/master/parts` | master | Доступные запчасти |
| GET | `/api/admin/spare-parts` | admin | Склад (`q`, `low_only`) |
| POST/PATCH/DELETE | `/api/admin/spare-parts...` | admin | Управление складом |
| GET/POST/PATCH/DELETE | `/api/admin/services...` | admin | Управление услугами |
| GET/POST/PATCH/DELETE | `/api/admin/employees...` | admin | Управление сотрудниками |
| GET | `/api/admin/orders` | admin | Все заявки |
| PATCH | `/api/admin/orders/{id}/assign` | admin | Назначить мастера |
| GET | `/api/stats/overview` | admin | Статистика для графиков |
| POST | `/api/uploads` | авторизованный | Фото устройства (до 5 МБ) |

Полное описание — в Swagger UI. Схема отдаётся в формате **OpenAPI 3.0.3**.

## Лендинг

Свёрстанный из PDF-макета лендинг «Rapier» — отдельная статическая страница,
смонтированная по адресу `/landing/` (`app/main.py` → `StaticFiles`).
Стили и скрипты не зависят от SPA и внешних CDN, изображения лежат в
`landing/assets/img/`. Поддерживаются адаптивные брейкпоинты 1180 / 1024 / 940 / 720 / 420 px
и мобильное меню-бургер.

## Настройки

Скопируйте `.env.example` в `.env` или задайте переменные окружения:

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite:///.../workshop.db` | Строка подключения SQLAlchemy |
| `JWT_SECRET` | dev-значение | **Обязательно смените в продакшене** |
| `ACCESS_TOKEN_TTL_MINUTES` | `720` | Время жизни токена |

### PostgreSQL

```powershell
pip install psycopg2-binary
$env:DATABASE_URL = "postgresql+psycopg2://workshop:workshop@localhost:5432/workshop"
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Таблицы создаются автоматически, демо-данные добавляются только в пустую базу.
Для чистой SQLite-базы достаточно удалить `workshop.db` и перезапустить приложение.

## Тесты

```powershell
.\.venv\Scripts\python.exe tests\smoke_test.py
```

Smoke-тест поднимает приложение через `TestClient` и проверяет полный сценарий:

квитанцию и публичную страницу `/r/{token}`, админ-эндпоинты, статистику,
а также ответы `401/403`.

## Безопасность и производительность

- Пароли хешируются bcrypt (без хранения открытого текста).
- JWT подписывается HS256, срок жизни настраивается.
- Проверка ролей на каждом защищённом эндпоинте.
- Валидация входных данных Pydantic и ограничения на размер/тип загрузок.
- Ответы API на демо-данных — единицы миллисекунд, что укладывается в требование < 3 с.
- Интерфейс адаптивный (mobile-first): брейкпоинты 1100/960/720/520 px,
  мобильное меню, прокручиваемые таблицы, перенос вкладок.
